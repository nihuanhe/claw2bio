# OFT Step 1 — 数据采集与校准

## Execution rule / 执行铁律

**Run the scripts in `scripts/` — do not write your own.**
The scripts here are the tested path; ad-hoc code generated by an agent is the
most common source of wrong results. Allowed changes, in order of preference:

1. Pass different CLI arguments (see Parameters below).
2. Copy the script to a scratch dir and make a **minimal** edit for a case the
   CLI cannot express — keep the change small and report exactly what changed.
3. Only if no script covers the task at all: write new code, run it, and then
   **fold it back into `scripts/`** so the next run reuses it.

每次执行前先读 `SKILL.md` 与 `examples/`；不要凭印象重写流程。

（中文摘要：本技能自带的 `scripts/` 是**经过验证的唯一推荐路径**。AI agent 执行时优先原样运行脚本、
只改命令行参数；确实需要改代码时，复制到临时目录做**最小改动**并说明改了什么；
只有完全没有对应脚本时才允许新写，且新写后必须回沉淀到 `scripts/`。禁止"凭印象重写一遍"。）

## 正常流程：Tracker 软件导出

Tracker 视频追踪软件正常工作 → 自动导出 `step,X,Y` CSV → 直接进入 [2_oft-analysis](../2_oft-analysis/)。

## 补救流程：手动录制（仅 Tracker 失效时）

当 Tracker 软件无法正常工作时，使用本工具手动逐帧点击记录坐标：

1. 运行 `tracker.py`
2. 打开小鼠 OFT 视频（暂停到起始帧）
3. 按 **F2** 开始录制
4. 逐帧前进视频，每次左键点击小鼠鼻子/身体中心位置
5. 按 **F2** 暂停，按 **Esc** 保存 `record.csv` 并退出

```bash
python tracker.py
```

## 校准参考

### 视频参数
- 帧率：25 FPS，每帧间隔 0.04 秒

### Arena 边界坐标（像素坐标系）
| 角 | X | Y |
|----|---|---|
| 左上 | 908 | 384 |
| 右上 | 1269 | 385 |
| 左下 | 908 | 746 |
| 右下 | 1271 | 743 |

### Pixel → cm 换算
- 已知 Arena 边长 = 50 cm
- 像素跨度 ≈ 1270 - 908 = 362 px
- **px_per_cm ≈ 362 / 50 = 7.24**

### 校准方法
1. 在视频全屏暂停状态下，用 `tracker.py` 分别点击 Arena 左下角和右下角
2. 记录两组 X 坐标，计算像素跨度
3. 像素跨度 / 真实边长（cm）= px_per_cm

详细文档：`像素和现实尺寸转换.txt`；操作演示 PPT：`tracker-full-screen.pptx`
（`record.csv` 为一次真实手动录制的输出实例，723 个坐标点，格式即 `step,X,Y`。）

## 输出

- `record.csv`：格式 `step,X,Y`，直接输入 [2_oft-analysis](../2_oft-analysis/) 进行后续分析

## 注意事项

- 默认录制上限 1000 次点击（可在代码中调整 `MAX_CLICKS`）
- 轨迹窗口实时显示最近点击位置
- 如果 `record.csv` 被 Excel 等程序占用，会自动生成带时间戳的备份文件
- 校准后注意验证计算结果——如小鼠运动速度是否在合理范围内（C57BL/6 通常 3-8 cm/s）
